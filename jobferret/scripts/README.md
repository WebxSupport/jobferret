# JobFerret scripts

Helpers the skill calls. The contract is `../ARCHITECTURE.md` §2–4. Every script has
`--help` (purpose, usage, exit codes) and `--json`. `jf_net.py` is the only module that opens a socket. `outreach.py verify --check-domain` and the discovery scripts (`discover.py`, `screen.py` for the sponsor register, `hunt_cron.py`) go through it, and all of them accept `--offline`. `jf_net.fetch` refuses every host on `NEVER_FETCH_DOMAINS` (LinkedIn, Indeed, Glassdoor, Totaljobs and its sister sites), including at each redirect hop, so a script cannot reach them by accident. Indeed is read in the user's own browser instead (`discover.py browse`, below).

Install: `python -m pip install -r requirements.txt` (Python 3.11+).
User data lives in `~/.jobferret`, or `$JOBFERRET_HOME` if set (tests use this).

## Usage

| Script | One-line usage |
|---|---|
| `setup_check.py` | `setup_check.py [--create] [--set KEY=VALUE ...] [--json]`: check Python, packages, Word/LibreOffice; with `--create` make `~/.jobferret` (cv/, applications/, config.toml, RUN, jobferret.db). Never overwrites. `--set browser.preferred=pane` writes one `config.toml` value (repeatable; dotted keys, TOML types). |
| `cv_extract.py` | `cv_extract.py <cv.pdf/.docx/.md/.txt> [--out ledger.json] [--text source.txt] [--force] [--fragment \| --min-lines N] [--json]`: plain text plus fact ledger; ledger `line` numbers are the line numbers in `--text`. `--fragment` accepts a pasted part of a CV (no line minimum; `"fragment": true` in `source` and the report). Refuses to overwrite a ledger without `--force` (which keeps a backup). Job headers of one to three lines in any order are split into title, employer, location and dates using `lexicon/role_words.txt` and `lexicon/employer_words.txt` (edit those to teach it new words); a title alone on its line becomes a `title` fact whose parent is the role; a guess is marked `fields.confidence: "low"`. Divider rules are skipped. Damaged or password-protected files exit 4 with a reason; picture files are refused (no OCR). |
| `ledger_check.py` | `ledger_check.py <draft.md> --ledger ledger.json [--strict] [--strip --out clean.md] [--json]`: every list item, skills line and H3 entry header must cite `[F012]`, as must every numeric sentence; every number in a cited unit must appear in a cited fact (rule 7); superseded IDs are rejected; `[CONFIRM: …]` (alias `[ASK: …]`) blocks. |
| `ledger_add.py` | `ledger_add.py --ledger ledger.json --kind metric --text "<exact sentence>" [--parent F008] [--provenance user\|profile] [--asked "<question>"] [--confirmed] [--json]`; or `--confirm F041`; or `--supersede F041 --text "<new wording>" [--confirmed]`. Appends with the next ID; never deletes; atomic write. |
| `voice_lint.py` | `voice_lint.py <draft> --format cover-letter\|email\|linkedin-note\|hiring-manager\|cv-profile\|cv-bullets\|form-answer\|follow-up\|thank-you [--locale uk\|us] [--profile voice-profile.json] [--max-words N] [--lists-dir DIR] [--json]`. Cover letter 150–400 words. Citation and `[CONFIRM]` markers are stripped first; cv-* formats ignore markdown headers. A missing `--profile` file warns and skips the profile checks. `voice_lint.py --measure s1.txt s2.txt --json` measures a voice profile from samples. |
| `cv_render.py` | `cv_render.py <clean.md> --locale uk\|us --out cv.docx [--pdf] [--json]`; `--letter` renders a cover letter (`# Name`, contact line, optional `To:`/`Re:` lines, body from `Dear …`; today's date inserted). ATS-safe DOCX (+ PDF), then re-extracts and reports any source line missing or out of order. Refuses input that still has markers. `--preview` (implies `--pdf`) also writes `page-N.png` next to the output; `cv_render.py --preview-only <file.docx\|file.pdf> --out-dir <dir>` renders page PNGs of an existing CV (DOCX needs Word or LibreOffice) and prints each path with the page size in cm. |
| `ats_detect.py` | `ats_detect.py <url> [--html saved.html] [--json]` → platform, tier, playbook, board, job_id, canonical_url, note. Hosts on `NEVER_FETCH_DOMAINS` are named after the site; Totaljobs, CWJobs, Jobsite, Caterer, Milkround and Glassdoor get tier `prohibited-automation` and `playbooks/indeed-assist.md`; LinkedIn and Indeed stay `assist`. `note` is null except for these hosts, where it says the user applies on the site; for Indeed it says the site is read in the user's browser only, "Apply on company site" leads to the employer's ATS, and Indeed Apply is the user's click (G2). |
| `db.py` | `db.py [--db PATH] [--json] init\| migrate\| add-job --json '{…}'\| set-job-status <job_id> <status> [--reason T]\| set-screening <job_id> --fit N [--screen '{…}'] [--status S]\| jobs [--status S] [--since N] [--min-fit N] [--run ID]\| runs [list\|show <id>]\| add-application --json '{…}' [--update]\| set-status <app_id> <status>\| list [--status s] [--jobs]\| show <id>\| stats\| export [--out dir]\| dedup [--url U] [--company C --title T] [--days N]\| events add --kind <kind> [--application <id>] [--job <id>] --detail "<text>"`. `add-job`/`add-application` print the new id. `migrate` upgrades an older database in place. `set-job-status` and `set-screening` record hunt decisions and `screen.py` results on a job; `jobs` and `runs` read what `discover.py` stored. Methods: `ats-form`, `assist-linkedin`, `assist-indeed`, `assist-nhs`, `assist-other`, `email`, `manual`. `dedup` exits 1 only when an application already exists (same canonical URL, or same company with a similar title within 30 days). A job `discover.py` stored but nobody applied for exits 0 and is reported as `known_job`: `{"ok", "duplicate", "known_job": {job_id, company, title, status, applications}\|null, "matches": […], "days"}`. `stats` uses the local date and counts `wrong-field` events. `submitted_today` (the G7 count) covers `ats-form`, `assist-*`, `email` and unset methods; `manual` applications (made outside JobFerret) are left out and listed as `submitted_today_manual`. `submitted_today_assisted` is informational (the `assist-*` part of `submitted_today`). Only `ats-form` counts toward `auto_eligible` and `auto_eligible_progress` (20 submissions needed). A `manual` application gets no `submitted_at` unless you give one. |
| `profile_prefill.py` | `profile_prefill.py --ledger ledger.json --out profile.json [--merge] [--json]`: draft profile from the CV ledger (name, contact, location guess, current role, roles, education, skills, target titles). `--merge` never overwrites a value the user entered; `meta.prefill` records the guesses. Exit 1 if the ledger has nothing usable. |
| `setup_ui.py` | `setup_ui.py [--port 0] [--timeout 1200] [--dump] \| --prefill-only \| --from-json FILE`: local preferences page on 127.0.0.1 (token in the URL, Host and Origin checked). Prints `URL: …`, then `SAVED …` (exit 0) or `TIMEOUT …` (exit 2). `--from-json` applies chat answers with the same validation. Writes `profile.json` and `config.toml [sources] [limits] [ux]`. |
| `qa.py` | `qa.py add --key K --question "…" [--context] [--options a,b] [--default] [--mode] \| pending [--json] \| list [--all] \| answer <id> "<text>" [--force] \| drop <id>`: the question queue in `questions.json`; `answer` writes `profile.json` (`answer_bank[K]`, or the dotted path). A list field splits only on `;` or a new line, so "Data analyst, public sector" stays one item. Answering a question that is not pending exits 1 unless `--force`. |
| `track.py` | `track.py [--db PATH] due [--today D]\| log <app_id> --kind email\|call\|interview\|offer\|rejection\|note [--detail T] [--when D] [--reason T]\| set <app_id> [--status S] [--follow-up D\|clear] [--found-via S] [--cv-variant X] [--role-family F]\| timeline <app_id>\| funnel [--by found_via\|role_family\|cv_variant\|month]\| paste --application <id> (--file P\|--text T) [--json]`: the pipeline after submission. `due --json` returns `follow_ups`, `waiting_for_close` (submitted, but the job's closing date is still ahead; nothing is owed until it passes), `interviews`, `outreach_replies_owed`, `probably_ghosted`. |
| `outreach.py` | `outreach.py [--db PATH] contacts add\|list\|suppress`, `verify <email> [--check-domain] [--offline]`, `messages add\|list\|sent\|reply\|done\|due`, `export --out DIR`: contacts with their source, a suppression list, the message log and follow-ups. It never sends anything. `verify` checks syntax, and with `--check-domain` makes one HTTPS request through `jf_net` (refused without a request for never-fetch domains such as linkedin.com). |
| `memory_import.py` | `memory_import.py --from chatgpt\|claude\|claude-code\|codex\|text [PATH] [--from …] [--out FILE] [--merge] [--json]`: counts what the user does and cares about in their own past chats and memory files into `memory/signals.json` (counts and at most two short snippets per signal; no model, no network). |
| `state.py` | `state.py show \| set --mode M --step N [--of T] [--name] [--status running\|waiting\|done\|stopped] [--context JSON] \| clear`: the resumable run state in `state.json`. |
| `discover.py` | `discover.py run [--source a,b] [--since N] [--offline] [--dry-run] [--json] \| sources [--json] \| boards add <name> <board-url> [--platform P] \| boards list \| browse plan [--since N] [--json] \| browse ingest <files...> [--text] [--json] \| browse job <file> [--json]`: `run` runs the enabled sources in `sources/` (adzuna, reed, nhs, teaching, boards, rss, alerts), stores jobs with `db.add_job` and the description at `jobs/<id>.json`, records one run. Missing keys are skipped and named; Indeed (a browser source) is skipped with "read in your browser, not fetched". Never fetches `sources.NEVER_FETCH_DOMAINS`. Network only through `jf_net`. `browse plan` lists the Indeed search pages to open within `[sources.indeed]` `max_queries`, `max_pages_per_query` and `daily_page_cap`, each with a `save_as` file under `~/.jobferret/inbox/browse/` (exit 1 when the daily cap is reached or no browser source is enabled). `browse ingest` parses saved captures (globs allowed; `--text` for page text), stores the jobs under one run, counts the pages in `~/.jobferret/cache/browse-ledger.json` and reports a challenge page (exit 1 when nothing is stored or the kill switch is set). `browse job` stores one `/viewjob` capture with the full description and `extra.apply` (`company-site`, `indeed-apply` or `unknown`). `sources` shows "N of 20 pages read today, in your browser". |
| `browse/` | `indeed_cards.js` (an Indeed search page) and `indeed_job.js` (an Indeed `/viewjob` page): read-only JavaScript the model runs with the browser's JavaScript action (`javascript_tool`, Playwright `browser_evaluate`). No clicks, no requests, no storage; each returns a JSON string to save as the file `browse plan` names, then `discover.py browse ingest` or `browse job`. Not run by any Python script. |
| `screen.py` | `screen.py [--run ID \| --all-new] [--offline] [--json]`: deterministic pre-screen against `profile.json` using `lexicon/uk_phrases.toml`; writes `fit_pre` and `screen_json`; exclusions name the rule and matched text; flags include likely duplicates and the sponsor-register check. |
| `digest.py` | `digest.py [--date YYYY-MM-DD] [--top N] [--out path] [--json]`: writes `digests/YYYY-MM-DD.md`; calls `track.py due --json` and `qa.py pending --json` when present. |
| `hunt_cron.py` | `hunt_cron.py [--since N] [--offline] [--json]`: discover + screen + digest, no model; exit 0 when a digest was written, 1 when nothing could run or `RUN` is missing. |
| `jf_common.py` | Shared helpers (paths, config, ledger I/O, CV markdown parser, sentence splitter, URL canonicaliser). `python jf_common.py [--json]` prints the resolved user dir and config, with the value of any key, secret, token or password setting shown as `***`. |

Typical cv-audit chain:

```
cv_extract.py cv.pdf --out ~/.jobferret/cv/ledger.json --text source.txt
ledger_check.py master.md --ledger ledger.json --strict          # must exit 0 first
ledger_check.py master.md --ledger ledger.json --strict --strip --out master.clean.md
voice_lint.py master.md --format cv-profile        # lints the Profile section only
voice_lint.py master.md --format cv-bullets        # lints the list items only
cv_render.py master.clean.md --locale uk --out master.docx --pdf
cv_render.py letter.clean.md --letter --locale uk --out cover-letter.docx --pdf
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | OK / pass. (`ats_detect` returns 0 for unknown URLs too: platform `generic`, tier `unknown`.) |
| 1 | Check failed or validation error: `ledger_check` rule 1, 2, 3 or 7 violations; `voice_lint` fail; `cv_extract` too few lines (10, `--min-lines`, none with `--fragment`), no usable text or garbled text (ledger not written); `cv_render` text missing/out of order or unsafe structure; `ledger_add` bad kind/parent/ID or already superseded; `db` not found / exists / invalid value / **an existing application matches** (`dedup`); `setup_check` not ready. |
| 2 | `ledger_check` only: blocked by `[CONFIRM]`/`[ASK]` markers, or by unconfirmed facts under `--strict`. If there are also rule 1–3 or 7 violations the code is 1. |
| 3 | A required package is missing; the exact `pip install` line is printed. |
| 4 | Usage or input error: bad arguments (argparse's own 2 is remapped, because 2 means "blocked"), unreadable file, invalid JSON, markers in `cv_render` input, a `--letter` without a `Dear` line, existing ledger without `--force`. |

## Tests

`python -m pytest tests -q`. Layout fixtures for the extractor (synthetic text in the layouts real CVs use) are in `tests/fixtures/layouts/`; their tests are `tests/test_layouts.py`. Fixtures: `tests/fixtures/sample-cv-uk.md` (fictional
two-page UK CV in §3 format, with citations), `sample-ledger.json`,
`clean-cover-letter.md` (cited) and `sample-letter-uk.md` (clean, for `--letter`). The
CV DOCX/PDF are generated in a session fixture and copied to `tests/fixtures/` for
inspection. PDF tests skip when neither Word + docx2pdf nor LibreOffice is available.
Voice tests run against `tests/fixtures/lists/` and the real `references/voice/lists/`
(skipped if those are absent).
